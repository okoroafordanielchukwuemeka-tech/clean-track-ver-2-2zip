PHASE 7.19A — PRODUCTION INFRASTRUCTURE AUDIT & RAILWAY PREPARATION

OBJECTIVE

This phase prepares CleanTrack for its first production deployment.

DO NOT deploy to Railway yet.

DO NOT connect the custom domain yet.

DO NOT configure Meta WhatsApp.

DO NOT switch Paystack to Live.

DO NOT build new business features.

This phase exists only to ensure the application is production-ready before deployment.

If any issue is discovered:

1. Identify the root cause.
2. Fix it.
3. Re-test.
4. Continue until the system is production-ready.

No shortcuts.

────────────────────────────

STEP 1 — Production Readiness Audit

Audit the complete project.

Verify:

• Frontend
• Backend
• Database
• Storage
• Authentication
• Billing
• Multi-Branch
• Worker Permissions
• Upload System
• Receipt Printing
• Search
• Notifications
• Background Tasks

Identify anything that could fail in production.

────────────────────────────

STEP 2 — Environment Variables Audit

Verify every required environment variable.

Examples include:

• DATABASE_URL
• EXTERNAL_DATABASE_URL
• JWT_SECRET
• SESSION_SECRET
• STORAGE_PROVIDER
• PAYSTACK_PUBLIC_KEY
• PAYSTACK_SECRET_KEY
• WHATSAPP placeholders
• Email configuration
• Upload configuration

Confirm:

No secrets are hardcoded.

Every missing variable is documented.

Application fails gracefully when variables are missing.

────────────────────────────

STEP 3 — Railway Compatibility Audit

Verify the project is fully compatible with Railway.

Audit:

• package.json
• start command
• build command
• tsx usage
• production scripts
• health endpoint
• static assets
• uploads
• environment loading
• migrations

Identify anything that would prevent Railway deployment.

Fix all issues.

────────────────────────────

STEP 4 — Database Audit

Verify:

• Production migrations
• Schema consistency
• Foreign keys
• Constraints
• Indexes
• Seed independence

Confirm:

Application starts correctly on an empty production database.

Database migrations are idempotent.

No duplicate migrations.

────────────────────────────

STEP 5 — File Storage Audit

Verify:

Logo uploads

Future receipt assets

Images

Storage paths

Persistence

Confirm:

Uploads survive application restarts.

No temporary development paths remain.

Storage abstraction is production-ready.

────────────────────────────

STEP 6 — Error Handling Audit

Audit every API.

Verify:

Proper HTTP codes

Validation

Unexpected errors

Database failures

Timeouts

Graceful degradation

No stack traces exposed to users.

────────────────────────────

STEP 7 — Logging & Monitoring

Verify:

Structured logging

Error logging

Startup logs

Critical failures

Health endpoint

Request tracing where appropriate

Application startup status

Add production-safe logging where necessary.

JWT security

CORS

Rate limiting

Helmet

No sensitive information exposed in logs or API responses.
